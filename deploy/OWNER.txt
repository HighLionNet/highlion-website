HIGHLION DEBIAN CUT-IN (HLv8 / hl8j)

1. Sync git to disk in this direction only:
     sudo rsync -a --delete --exclude '.git/' /path/to/highlion-website/ /var/www/highlion/
   The copy is typed in git. From now on, do not edit live HTML and forget to copy it back.

2. Install and include both nginx snippets:
     sudo cp /var/www/highlion/deploy/nginx-headers.conf /etc/nginx/snippets/highlion-headers.conf
     sudo cp /var/www/highlion/deploy/nginx-api.conf /etc/nginx/snippets/highlion-api.conf
   Inside the www.highlion.net server block:
     include snippets/highlion-headers.conf;
     include snippets/highlion-api.conf;
   Keep /api/ outside the IL geo map, then run:
     sudo nginx -t && sudo systemctl reload nginx

3. Purge the bare stylesheet URL from Cloudflare:
     https://www.highlion.net/css/style.css
   Purge both the bare URL and prior ?v=hl8i asset cache after deploying ?v=hl8j.
   Cloudflare dashboard → Caching → Purge Custom URL.

4. If the strict CSP breaks pages behind Cloudflare, disable Cloudflare Email Obfuscation and Rocket Loader for this zone. Keep script-src 'self'; do not add unsafe-eval or inline script permission.

5. Create the thumbnail store as www-data:
     sudo install -d -m 0750 -o www-data -g www-data /var/tmp/highlion-thumbs
   Confirm www-data can write /var/tmp/highlion-intel.json and /var/tmp/highlion-thumbs.json.

6. Confirm HEAD is accepted by every GET API:
     curl -sI https://www.highlion.net/api/intel.php
     curl -sI https://www.highlion.net/api/csrf.php
     curl -sI https://www.highlion.net/api/traffic.php
     curl -sI 'https://www.highlion.net/api/thumb.php?id=00'
   The first three must return 200, not 405. The invalid thumbnail must return 404, not 405.

7. Confirm the intel payload has at least six distinct thumbnail IDs:
     curl -s https://www.highlion.net/api/intel.php
   At least six items must match /api/thumb.php?id=<40 lowercase hex>.

8. Confirm the geo fence remains limited to the contact page:
     off-IL: curl -sI https://www.highlion.net/contact.html  → 403
     any-IP: /api/* remains reachable

9. Do not rsync .git. The rsync command in step 1 excludes it.

10. Leave assets/fonts/generate-fonts.sh unchanged. If local WOFF2 assets are missing, run the existing script exactly as before:
      sudo bash /var/www/highlion/assets/fonts/generate-fonts.sh

11. Leave the Telegram secret files on the Pi and unchanged:
      /etc/highlion/letterbox.env
      /etc/highlion/honeypot.env
    Keep both root:www-data mode 0640. Never copy either file into git.

12. Re-run the claim and honeypot tests:
      curl -s -H 'Origin: https://www.highlion.net' -H 'Content-Type: application/json' \
        --data '{"flag":"HL8{spare-field}","ts":0}' https://www.highlion.net/api/ctf.php
      → 200 ok, a new /var/tmp/highlion-ctf.log line, and a [HL CTF] Telegram through letterbox.env

      POST company:"bot" to /api/contact.php
      → 200 ok, a new /var/tmp/highlion-honeypot.log line, and the existing honeypot Telegram

   GET or HEAD on /api/contact.php must still take the bad-method honeypot path and return 405.

13. Configure full-machine leases and the owner-only emergency session. Do not run these from Codex:
      sudo install -m 600 -o root -g www-data /dev/null /etc/highlion/shell.env
      # owner writes:
      # HL_SHELL_SLOTS=8
      # HL_SHELL_TTL=90
      # HL_SHELL_HEARTBEAT=30
      # HL_OP_COOKIE=<long random>
      sudo mkdir -p /var/tmp
      sudo touch /var/tmp/highlion-shell-slots.json
      sudo chown www-data:www-data /var/tmp/highlion-shell-slots.json
      sudo chmod 660 /var/tmp/highlion-shell-slots.json
      # include deploy/nginx-shell-slot.conf next to the other
      # /api/ location
      # set cookie hl_op on the owner's browser only
      # purge Cloudflare cache for /css/style.css and ?v=hl8i assets

14. Raise HL_SHELL_SLOTS when hardware allows. Do not move the machine onto the host.
    The sealed-machine and pack notes are in js/shell/README-OWNER.txt.
