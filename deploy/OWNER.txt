HIGHLION / HLv8 / hl8t

DEPLOYMENT
Deploy the main branch to /var/www/highlion. Keep /etc/highlion/*.env outside the webroot and preserve the installed credentials. Never copy .git, .hl8t-work, environment files, or local tooling into the webroot. Remove the retired js/sfx.js and lab HTML files from an existing deployment.
Install deploy/nginx-api.conf and deploy/nginx-headers.conf in the server block, retaining the site's geo fence and correct PHP-FPM socket. Remove conflicting old exact shell-slot locations; the API location handles .php and directory aliases. Run nginx -t before reloading. The access rules deny deployment notes, scripts, dotfiles, source maps, private helpers, and retired lab paths. autoindex must remain off. Do not publish a source archive in the webroot.
All asset/include URLs use ?v=hl8t. Footer and X-HighLion remain HLv8. If fonts are absent, run assets/fonts/generate-fonts.sh on the host; the script is denied over HTTP.

IDENTITIES
Every tab starts as kali. su root is the public CTF privileged account: password only. su admin is the developer account: password plus the existing hl_op cookie. No password or hash changes are required.
Private /etc/highlion/shell.env keys: HL_ROOT_PW_HASH and HL_ADMIN_PW_HASH (password_hash output), HL_OP_COOKIE (existing random capability), HL_SHELL_SALT (stable random secret), HL_SHELL_SLOTS (default 8), HL_SHELL_TTL (default 90 seconds). ROOT_PW_HASH and ADMIN_PW_HASH remain compatible aliases. Keep the file owned by www-data with mode 0600.
hl_op keeps Domain=www.highlion.net, Path=/, Secure, HttpOnly, SameSite=Lax. PHP refreshes its existing value only after an admin password and cookie match. JavaScript never reads it. Removing the cookie revokes control on the next request. Root cannot moderate other sessions.
Authentication permits five failures per IP per ten minutes. Attempts are serialized per IP, including password verification. Slots bind a random ID, server session owner, salted client IP, and TTL. PHP's REMOTE_ADDR is authoritative: configure nginx real_ip only for explicitly trusted proxy ranges. Do not trust arbitrary forwarded headers. If a reverse proxy is used, verify real_ip before rollout or visitors may share its rate-limit bucket.

SESSIONS AND MODERATION
PHP requires a writable private session.save_path. hl_session is Secure, HttpOnly, SameSite=Lax and uses strict session IDs. Give this site its own session directory and retain session data for 86400 seconds. Admin login rotates the session ID and grants the authenticated slot control for 15 minutes; log in again after expiry. The underlying lease owner remains stable across rotation.
The PHP-FPM user must own /var/tmp/highlion-shell-slots.json (0600), /var/tmp/highlion-shell-auth (0700), and /var/tmp/highlion-letterbox (0700). Existing thumbnail and market caches remain under /var/tmp; preserve their www-data ownership. Never place these stores in the webroot.
sessionctl who shows this lease. After su admin, sessionctl list shows active leases, queued command counts, and the last acknowledged result. Commands: sessionctl lock ID, unlock ID, drop ID, clear ID, reset ID, fx ID on|off, and exec ID COMMAND. Quote COMMAND when it contains shell operators. Results arrive on subsequent heartbeats (25 seconds while visible). Hidden tabs apply control when visible again.
Exec operates only on the target's virtual files and simulated LAN. Authentication, claims, navigation, editors, and nested moderation are rejected during remote execution. No password input, browser storage, real host files, real commands, or external network access is exposed. Logs contain control type and abbreviated lease IDs, not commands, passwords, or output.
Drop terminates the current browser session; it is not an IP ban. Reset clears the simulated disk overlay, returns to kali, and keeps trophies. When the lease service is unavailable, kali remains usable and authentication fails closed. Explicit moderation stays in effect during an outage. Reloading starts a new simulated session.
