HIGHLION DEBIAN CUT-IN (HLv8 / hl8k)

1. Sync the git checkout to the web root in this direction only:
     sudo rsync -a --delete --exclude '.git/' /path/to/highlion-website/ /var/www/highlion/
   Never edit live HTML without copying the change back to git.

2. Keep the existing nginx snippets installed and confirm PHP-FPM serves /api/ outside the contact-page geo fence:
     sudo nginx -t && sudo systemctl reload nginx
     curl -sI https://www.highlion.net/api/intel.php
     curl -sI https://www.highlion.net/api/csrf.php
     curl -sI https://www.highlion.net/api/traffic.php
     curl -sI 'https://www.highlion.net/api/thumb.php?id=00'
   All four HEAD requests must be handled; an invalid thumbnail now redirects to /assets/thumbs/highlion.png.

3. Purge this Cloudflare URL after rsync, or rely on the new hl8k query token:
     https://www.highlion.net/css/style.css

4. Create the writable thumbnail and shell-lease stores:
     sudo install -d -m 0750 -o www-data -g www-data /var/tmp/highlion-thumbs
     sudo touch /var/tmp/highlion-intel.json /var/tmp/highlion-thumbs.json /var/tmp/highlion-shell-slots.json
     sudo chown www-data:www-data /var/tmp/highlion-intel.json /var/tmp/highlion-thumbs.json /var/tmp/highlion-shell-slots.json
     sudo chmod 0660 /var/tmp/highlion-intel.json /var/tmp/highlion-thumbs.json /var/tmp/highlion-shell-slots.json
   After one cold /api/intel.php request, confirm at least six items have distinct 40-character thumbnail IDs and every file in /var/tmp/highlion-thumbs is at most 204800 bytes.

5. Fix and verify the operator-only simulated root session. PHP-FPM must be able to read this file; 0600 root:www-data is wrong:
     sudo install -d -m 0750 -o root -g www-data /etc/highlion
     sudo touch /etc/highlion/shell.env
     sudo chown root:www-data /etc/highlion/shell.env
     sudo chmod 0640 /etc/highlion/shell.env
   Keep these values in that file, never in git:
     HL_SHELL_SLOTS=8
     HL_SHELL_TTL=90
     HL_SHELL_HEARTBEAT=30
     HL_OP_COOKIE=<long-random-secret>
   In the intended Firefox container, set cookie hl_op on www.highlion.net with Path=/, Secure, and SameSite=Lax. Reload the page, open DevTools Network, and inspect the acquire POST to /api/shell-slot.php: it must return mode:"full", operator:true. The terminal must then boot as root. While that operator lease is active, `su admin`, `su kali`, and `su root` switch immediately; no simulated password prompt exists. A normal browser without hl_op boots as kali and `su` fails immediately. Remove the cookie to remove operator access.

6. Keep /etc/highlion/letterbox.env and /etc/highlion/honeypot.env root:www-data mode 0640. Do not commit any /etc/highlion/*.env file. Re-run the existing contact, honeypot, claim, and geo-fence checks after deployment.

7. If local WOFF2 assets are missing, run the existing generator:
     sudo bash /var/www/highlion/assets/fonts/generate-fonts.sh
   Deploy 403.html and 404.html explicitly if nginx error_page routing does not already use them.

8. Deferred owner checks: remove any legacy duplicate X-HighLion header at the nginx/Cloudflare layer; confirm /api/thumb/ is routed to its index.php rather than an nginx directory-listing 403; keep the current .ico social preview until a dedicated Open Graph image exists; review privacy/terms/cookie copy if policy requires it; harden rate-bucket filenames if shared-host threat assumptions change; verify mobile hash rows after CDN transforms. The contact-page off-IL 403 is intentional. Public lab flags remain intentional.

9. Scope note: full-quality simulated ping, nmap, nc, traceroute/tracepath, DNS, ssh, curl, and wget are shipped. Branded offensive suites (hydra, sqlmap, msfconsole, nikto, gobuster, dirb, enum4linux, smbclient, crackmapexec) remain deliberately unavailable rather than shipping shallow emulations.
